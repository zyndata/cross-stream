# Repository structure

Single private GitHub repo. One Go module at the root (`go.mod`), plus the
Android project and the Wails GUI in subfolders.

```
.
├── CLAUDE.md                 # Claude Code rules (short, loaded every session)
├── Makefile                  # build, test, lint, aar, e2e, docker
├── go.mod / go.sum
├── cliff.toml, CHANGELOG.md  # git-cliff config; changelog is generated, never hand-edited
├── .claude/
│   ├── settings.json         # permissions: allowed commands, denied reads
│   ├── commands/
│   │   ├── phase.md          # /phase NN   — run one phase
│   │   └── phase-done.md     # /phase-done NN — verify, summarize, commit, push, CI
│   └── skills/release/SKILL.md # /release — local deploy or SemVer tag release (phase 17+)
├── cmd/
│   ├── xs-server/              # server daemon
│   ├── xs-ctl/              # server CLI (enroll, list, revoke, sessions)
│   ├── xs-hubd/                 # hub daemon (Linux systemd; Windows service, phase 16)
│   ├── xs-hubctl/               # hub CLI for headless testing (status, pair-qr, enroll)
│   └── xs-relaysim/             # relay core as a Linux binary (tests)
├── internal/
│   ├── wire/                 # outer header, frames, encode/decode (no I/O)
│   ├── crypto/               # Noise wrappers, AEAD, replay window, key files
│   ├── bond/                 # path state, scheduler, reorder, ACK, failover
│   ├── session/              # session lifecycle on top of bond (shared hub/server)
│   ├── tun/                  # TUN abstraction (wireguard-go tun: Linux + Wintun)
│   ├── iphlp/                # Windows IP Helper API wrappers (addresses, routes, interface MTU/metric/forwarding)
│   ├── server/               # xs-server logic: listener, sessions, NAT setup, state store
│   ├── enroll/               # XS1 enrollment codes + token store
│   ├── pairing/              # XSR1 QR payload, relay registry
│   ├── control/              # hub↔relay control channel (both ends)
│   ├── transport/            # relay↔server transports: udp, tcp, wss (phase 10)
│   ├── relay/                # relay core (data relay, proxy role, Binder, stats)
│   ├── hub/                  # xs-hubd orchestration + mode state machine
│   ├── hub/netcfg/           # hotspot, routes, NAT, uplink scan: Linux (NetworkManager, nft) and
│   │                         #   Windows (Mobile Hotspot + ICS via embedded PowerShell, winps/)
│   ├── hub/usage/            # per-relay daily usage + speed-test history (phase 11)
│   ├── hub/tpmkey/           # hub static key sealed by the TPM 2.0 (go-tpm, phase 14)
│   ├── hub/hublog/           # in-memory log ring + redaction for log export (phase 14)
│   ├── hub/uplink/           # local uplinks: interface scan, link registry, ModemManager (phase 12)
│   ├── datacap/              # data cap per session/day/month + throttle (relays, local links)
│   ├── pep/                  # split-TCP streams over the bond (phase 13)
│   ├── server/admin/         # admin operations shared by xs-ctl and the web panel
│   ├── webui/                # server web panel: HTTP API, auth, embedded assets (phase 15)
│   ├── direct/               # DIRECT mode: netstack, flow table, relay selection
│   ├── dns/                  # hub DNS forwarder
│   ├── update/               # release check + hub self-update: GitHub releases/latest, SHA256SUMS, unpack, install.sh / install.ps1 (phase 18)
│   ├── ipc/                  # JSON-RPC over a Unix socket (AF_UNIX on Windows too) (xs-hubd ↔ GUI/xs-hubctl)
│   └── stats/                # rate meters, counters
├── mobile/                   # gomobile bind entry package (thin API over internal/relay)
├── android/                  # Android Studio project (Kotlin, Compose)
│   └── app/libs/xscore.aar # generated by `make aar` (git-ignored)
├── gui/                      # Wails v2 app (Go bindings + Svelte frontend)
├── webui/                    # Svelte frontend of the server web panel (built into internal/webui)
├── deploy/
│   ├── public/paths.txt, forbidden.txt, export.sh  # allowlisted public export + leak check (never exported)
│   ├── server/Dockerfile, docker-compose.yml (+ .host.yml), server.example.yaml,
│   │         remote-deploy.sh (SSH deploy + health check + rollback), hyperv/new-test-vm.ps1

│   └── hub-windows/install.ps1  # Windows hub: service, group, firewall (`make hub-windows` builds bin/windows)
├── ha/                       # Home Assistant app repository (phase 17b)
│   ├── repository.yaml       # copied to the public repo's root by the export
```

## Dependency rules
- `wire`, `crypto` depend on nothing internal.
- `bond` depends on `wire` only. `session` on `bond`, `crypto`, `wire`.
- `relay` must not import `hub`, `server`, `direct` (it is compiled for Android).
- Only `hub/netcfg`, `tun` and `iphlp` (Windows IP Helper API wrappers, used by both) contain OS-specific code (`_linux.go`, `_windows.go`).
- `cmd/*` are thin: flag parsing, config loading, wiring.

## Main libraries
- `github.com/flynn/noise`, `golang.org/x/crypto/chacha20poly1305`
- `golang.zx2c4.com/wireguard/tun` (TUN on Linux, Wintun on Windows)
- `gvisor.dev/gvisor/pkg/tcpip` (DIRECT mode netstack)
- `github.com/skip2/go-qrcode` (QR PNG for the GUI; terminal QR in xs-hubctl)
- `golang.org/x/mobile/cmd/gomobile` (AAR)
- `gopkg.in/yaml.v3`
- Android: Jetpack Compose, CameraX + ML Kit barcode scanning (bundled model)
